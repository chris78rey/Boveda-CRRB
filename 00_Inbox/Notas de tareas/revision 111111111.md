Sí. Según tu salida, los índices están actualmente en `TBDATOSG`. Si deseas llevarlos al tablespace de índices `TBINDICES_SIS`, hazlo así.

Primero verifica cuánto ocupan:

```
SELECT SUM(s.bytes) / 1024 / 1024 AS mb_indices
FROM dba_segments s
JOIN dba_indexes i
  ON i.owner = s.owner
 AND i.index_name = s.segment_name
WHERE i.owner = 'SIS'
  AND i.table_name = 'CUENTAS_JN'
  AND i.tablespace_name = 'TBDATOSG';
```

El resultado debe ser menor que los aproximadamente **2.573 MB libres** de `TBINDICES_SIS`.

Genera los comandos de movimiento:

```
SELECT
  'ALTER INDEX ' || owner || '.' || index_name ||
  ' REBUILD TABLESPACE TBINDICES_SIS;'
FROM dba_indexes
WHERE owner = 'SIS'
  AND table_name = 'CUENTAS_JN'
  AND tablespace_name = 'TBDATOSG'
  AND index_type = 'NORMAL'
ORDER BY index_name;
```

El resultado será parecido a:

```
ALTER INDEX SIS.CUENTAS_JN_ANIO_I
REBUILD TABLESPACE TBINDICES_SIS;

ALTER INDEX SIS.CUENTAS_JN_ANIOA_I
REBUILD TABLESPACE TBINDICES_SIS;

ALTER INDEX SIS.CUENTAS_JN_FECHA_I
REBUILD TABLESPACE TBINDICES_SIS;

ALTER INDEX SIS.CUENTAS_JN_PACIENTE_I
REBUILD TABLESPACE TBINDICES_SIS;
```

Ejecuta todos los comandos generados y luego verifica:

```
SELECT index_name,
       tablespace_name,
       status
FROM dba_indexes
WHERE owner = 'SIS'
  AND table_name = 'CUENTAS_JN'
ORDER BY index_name;
```

El resultado esperado es:

```
TABLESPACE_NAME
---------------
TBINDICES_SIS
```

El movimiento requiere espacio temporal porque durante el `REBUILD` pueden coexistir el índice antiguo y el nuevo. No ejecutes el movimiento si el tamaño total de los índices supera el espacio libre de `TBINDICES_SIS`. Oracle permite mover un índice mediante `ALTER INDEX ... REBUILD TABLESPACE`.
